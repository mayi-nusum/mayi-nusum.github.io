Vistara Design System

One visual language, a reusable component library and clear standards for designers and developers.

Overview

A design system built to standardise Vistara's product UI, from brand elements to reusable components. It covers foundations (colour, typography, spacing, iconography), components (buttons, forms, cards, modals and more) and standards (naming, variables and developer handoff).

The challenge

One product, many dialects.

  • Inconsistent visual language: similar colours, type sizes and spacings used differently from screen to screen.
  • Duplicated components: the same button, form field or card rebuilt several times, each slightly different.
  • Slow, unclear handoff: developers guessing values and states because rules were not written down.

The brief: find the gaps in the existing design language, standardise what is used most, and give every team one source of truth.

Process

  • Audit: every UI element was logged in a spreadsheet, compared and given a decision (consolidate, merge or standardise).
  • Align: heard what PMs, designers and developers need and where they lose time.
  • Foundations: colour, type scale, a 4pt spacing grid and icons.
  • Components: buttons, forms, cards and modals built as one flexible version each.
  • Standards: implementation rules, variables and specs with developers.
  • Maintain: a request, review, dev-check and release loop with a changelog.

Outcome

Consistency across screens and teams, faster design work (designers assemble rather than rebuild), clear handoff where specs and tokens replace guesswork, and a base new products can start from.

  • Audit first. The inventory made every later decision easier to defend.
  • Name things for meaning, not looks. Semantic tokens make change cheap.
  • Involve developers early so the system is built the way it is designed.
